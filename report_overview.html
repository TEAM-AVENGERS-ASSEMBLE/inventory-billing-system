🎯 Problem Statement & Engineering Objectives

Problems in Traditional Manual Retail (Slide 2):

  • No Live Stock Count: Stock balances only discovered after physical checks, causing customer stockouts.
  • Manual, Error-Prone Invoicing: Math errors in rushed mental totals and tax additions.
  • Zero Low-Stock Warning: Fast-moving goods deplete completely with no warning.

The Engineered Digital Solution (Slide 3):

  • Real-Time Stock Synchronization: Every sale atomically updates inventory stock quantities.
  • Single-Step Receipt Generator: Point-and-click billing with automated 5% GST and instant receipt.
  • Low-Stock Warning Center: Automated flags when $\text{Stock} \le \text{Threshold}$ with restock shortcuts.
💻 Technology Stack (Slide 4 — "No Frameworks Policy")
Layer Technology Architectural Role & Justification
Frontend HTML5, CSS3, Modern JavaScript Classic business UI, Fetch API, live cart calculation, printable media rules.
Backend Java Servlets (Servlet 4.0 API) Lightweight HTTP request dispatching, JSON serialization (Gson), no Spring/framework bloat.
DB Access JDBC API (java.sql.*) PreparedStatements, explicit transaction control (commit / rollback), connection safety.
Database MySQL 8.0 (InnoDB Engine) ACID relational data storage, foreign key constraints, row-level locking.
⚡ Core Transaction Workflow (Slide 5 Single-Request Flow)
Atomic Execution Pipeline: Single Request Checkout & Inventory Deduction
1. Billing Screen Cashier picks items; total is auto-calculated.
➔
2. BillingServlet Reads order payload; opens JDBC transaction.
➔
3. Row-Level Lock SELECT ... FOR UPDATE verifies stock limits.
➔
4. MySQL Update Deducts stock, writes sale & items; commits.
➔
5. Instant Receipt Sends back JSON; renders formal Tax Invoice.

🧾 Formal Commercial Tax Invoice (Saurabh Mishra)

Commercial Tax Invoice Specification:

  • GSTIN Registered Tax Header: 27AABCS1429B1Z | State Code 27.
  • Tax Split Itemized Taxable Subtotal, CGST @ 2.50%, and SGST @ 2.50%.
  • Words Dynamic Amount in Words (e.g. "Indian Rupees Five Hundred Forty-One Only" via Indian currency converter).
  • Legal 3-point return policy, municipal jurisdiction & authorized sign box.

Classic Business POS Interface:

  • High-contrast slate/navy theme with crisp tabular lines.
  • Real-time cart quantity steppers with stock ceiling checks.
  • Dual-Mode API client (api.js) enabling seamless live Java/MySQL connection or instant standalone browser presentation mode.
📊 Multi-Period Sales & Product Analytics

Reporting Horizons:

  • 📅 End of Day (Z-Report): Daily register balance, gross sales revenue, completed invoice count, and average order basket value.
  • 🗓️ End of Week (7 Days): Weekly revenue trajectory & daily turnover.
  • 📊 End of Month (Turnover): Monthly movement & category split.

Analytical Metrics & Features:

  • Product Volume Ranking: Identifies bestsellers alongside remaining stock to prevent stockouts of high-demand items.
  • Category Contribution: Percentage revenue split across departments.
  • One-Click Management Printing: Dedicated store summary print format.
